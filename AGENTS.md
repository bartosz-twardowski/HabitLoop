# Repository Guidelines

HabitLoop is an adaptive habit tracker built with Astro 6 (SSR on Cloudflare Workers), React 19 for interactive components, Supabase for auth and data, and Tailwind CSS 4. Full spec at `@context/foundation/prd.md`; tech decisions at `@context/foundation/tech-stack.md`.

## Hard Rules

- Never write to `context/archive/`. Archived changes are immutable.
- Always use `@/` path alias for imports (`@/lib/supabase`, not `../../lib/supabase`). Configured in `@tsconfig.json`.
- Construct the Supabase client via the factory in `@src/lib/supabase.ts` — never import a singleton.
- Server-only env vars (`SUPABASE_URL`, `SUPABASE_KEY`) are defined in `@astro.config.mjs` with `context: 'server'` — never expose them to the client bundle.
- `src/types/database.ts` is generated by `npx supabase gen types typescript --local`. Never hand-edit it; see `@context/foundation/lessons.md` L-002.
- Never edit existing migration files in `supabase/migrations/`. Add a new timestamped file instead.

## Commands

| Command | Purpose |
|---------|---------|
| `npm run dev` | Astro dev server (Cloudflare workerd runtime) |
| `npm run build` | Production build |
| `npm run lint` | ESLint with type-checked rules (runs `astro check`) |
| `npm run lint:fix` | ESLint with auto-fix |
| `npm run format` | Prettier (120-char lines, trailing commas) |
| `npx supabase start` | Local Postgres + Auth + Studio (requires Docker) |
| `npx supabase db reset` | Re-apply all migrations from scratch |
| `npx wrangler deploy` | Deploy to Cloudflare Workers |

## Project Structure

- `src/components/` — React `.tsx` only where client-side interactivity is needed (forms, toggles). Use `.astro` for static/layout.
- `src/lib/supabase.ts` — Supabase client factory. All routes and pages use this.
- `src/middleware.ts` — Auth session check on every request. Add new protected paths to the `PROTECTED_ROUTES` array.
- `src/pages/` — File-based routing: `.astro` for pages, `api/*.ts` for JSON/form endpoints.
- `src/styles/global.css` — Tailwind v4 config via `@theme` blocks. No `tailwind.config.*` file.
- `src/types/database.ts` — Generated Supabase types. Regenerate after schema changes.
- `supabase/migrations/` — Incremental SQL migrations applied by `npx supabase db reset`.
- `context/foundation/` — PRD, roadmap, tech-stack, lessons learned.
- `context/changes/` — Active change plans, reviews, and implementation progress.

## Coding Conventions

- TypeScript strict mode (`astro/tsconfigs/strict`). Husky + lint-staged run ESLint and Prettier on commit.
- Runtime validation (Zod) is required at API boundaries for values the generated types cannot constrain — `frequency` (1–7 integer) and `completed_on` (ISO date string). See `@context/foundation/lessons.md` L-003.

## Commit & PR Conventions

Conventional Commits with scope matching the change ID: `feat(data-schema):`, `fix(auth):`, `chore(archive):`. CI gate at `@.github/workflows/ci.yml` runs `lint` then `build` on push/PR to `master`.
